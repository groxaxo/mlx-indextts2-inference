# mlx-indextts2 Project Notes

## Scope

Local MLX runtime for IndexTTS / IndexTTS2 on Apple Silicon. This checkout is used as the safer replacement path for `/Users/vanch/index-tts` when MPS memory pressure is too high.

## Runtime

- Package manager: `uv`
- CLI entrypoint: `mlx-indextts`
- Primary package: `mlx_indextts/`
- Local model root: `models/`
- Speaker cache root: `speakers/`
- Benchmark and upload scripts: `scripts/`
- Shared runtime wrapper: `mlx_indextts/runtime.py`
- M3 Max runtime tuning helper: `mlx_indextts/performance.py` resolves MLX memory/cache limits and bounded PyTorch preprocessing threads.
- MLX-native Qwen emotion wrapper: `mlx_indextts/qwen_emotion.py`
- Optional Demucs reference-audio cleanup: `mlx_indextts/audio_denoise.py`
- Novel/dialogue batch planner: `mlx_indextts/novel_planner.py`
- Local API server: `mlx_indextts/api_server.py`
- Lightweight Gradio WebUI: `mlx_indextts/webui.py`

## Local Model Defaults

The CLI defaults to local 8bit IndexTTS2 models:

- Standard profile: `models/mlx-indexTTS2-standard-8bit`
- Vietnamese profile: `models/mlx-indexTTS2-vietnamese-8bit`

Environment overrides:

- `MLX_INDEXTTS_STANDARD_MODEL`
- `MLX_INDEXTTS_VIETNAMESE_MODEL`

Vietnamese text with tone marks is auto-routed to the Vietnamese 8bit model when `--profile auto` is used.

## Commands

Generate:

```bash
uv run mlx-indextts generate -r speakers/ban_khoe_vietnamese_v2.npz -t "Đêm nay gió rất nhẹ." -o outputs/example.wav
```

Batch:

```bash
uv run mlx-indextts batch -i input.txt -r speakers/ban_khoe_vietnamese_v2.npz -o outputs/batch --profile vietnamese --combine
```

CSV batch input can optionally provide per-row `ref_audio` or `reference_audio`. When every CSV row has a reference path, `--ref-audio` is optional; this is used for multi-speaker dialogue generation.
CSV batch input also accepts original index-tts-style Chinese columns: `文本`, `音色参考音频`, `上传情感参考音频`, `情感权重`, `情感描述文本`, and `喜/怒/哀/惧/厌恶/低落/惊喜/平静`.

Plan a novel/dialogue script into batch CSV:

```bash
uv run mlx-indextts plan -i script.txt -o outputs/batch_plan.csv
```

Denoise a reference audio file, or denoise automatically during generation:

```bash
uv sync --extra denoise
uv run mlx-indextts denoise -i ref.wav -o outputs/ref_denoised.wav
uv run mlx-indextts generate -r ref.wav -t "Hello" -o outputs/example.wav --denoise-ref
```

The denoise extra pins `torchcodec>=0.10,<0.11` because this project currently resolves PyTorch 2.10; TorchCodec 0.11 is for PyTorch 2.11 and fails to load on this environment.
Reference audio cleanup is now the default for `generate`, `batch`, and `speaker`.
Use `--no-denoise-ref` only when you intentionally want the raw source.

IndexTTS2 emotion/speaker disentanglement is exposed in MLX entrypoints:

- CLI single generation: `--emotion-ref-audio <path-or-npz>`
- CLI batch default: `--emotion-ref-audio <path-or-npz>`
- CSV row override columns: `emotion_ref_audio`, `emotion_reference_audio`, `emo_ref_audio`, `emotion_audio`, or `emo_audio`
- Emotion sources are mutually exclusive. Use exactly one of `--auto-emotion` / `--emotion auto-qwen`, manual `--emotion`, or `--emotion-ref-audio` / CSV emotion reference columns.
- Qwen auto emotion weights are normalized to a full total and generated with `emo_alpha=1.0` so text emotion does not fall back to the speaker reference's residual emotion.

API:

```bash
uv sync --extra api
uv run mlx-indextts-api
```

WebUI:

```bash
uv sync --extra webui
uv run mlx-indextts-webui
```

Qwen text emotion conversion:

```bash
uv sync --extra qwen
uv run python scripts/convert_qwen_emotion_mlx.py
```

If the converted Qwen model already exists, the converter exits without needing
the original checkpoint. To reconvert, provide `--source` or set
`MLX_INDEXTTS_QWEN_EMOTION_SOURCE`.

emotion2vec audio emotion library:

```bash
uv sync --extra emotion2vec
uv run mlx-indextts emotion2vec --input /path/to/audio_clips --output-dir outputs/emotion_library
uv run mlx-indextts plan -i script.txt -o outputs/batch_plan.csv --emotion-library outputs/emotion_library/catalog.csv
```

For scene libraries from `video-library`, `plan` can match emotion reference
clips by scene/emotion/gender/age and write speaker voice references:

```bash
uv run mlx-indextts plan -i script.txt -o outputs/batch_plan.csv \
  --emotion-library outputs/fjymb_library_final/catalog.csv \
  --emotion-scene crosstalk \
  --auto-duo-refs \
  --speaker-ref "逗哏=/path/to/a.wav" \
  --speaker-ref "捧哏=/path/to/b.wav" \
  --speaker-profile "逗哏=male:adult" \
  --speaker-profile "捧哏=male:adult"
```

Background Hugging Face upload:

```bash
launchctl print gui/$(id -u)/com.vanch.mlx-indextts-hf-upload
tail -f outputs/hf_upload_logs/launchctl-upload-current.log
```

## Upload And Cleanup Policy

`scripts/upload_hf_models_background.sh` uploads all fp32, fp16, and 8bit model directories to `vanch007/*` Hugging Face repos. It verifies required remote files before deleting local non-8bit model directories. Do not manually remove fp32/fp16 directories until the script finishes successfully.

## Safety / Performance Notes

- GPT top-p sampling and repetition penalty stay on MLX tensors; avoid adding NumPy/Python scatter loops inside per-token generation.
- API output and served audio paths are restricted to `outputs/` to avoid arbitrary local file reads through `/audio`.
- Qwen batch emotion now uses speaker-aware smoothing plus adaptive `emo_alpha`; batch CSV should carry `speaker` (or `role`) for dialogue stability.
- 2026-05-12: Added `--target-duration` and explicit `--fit-duration` for
  duration-oriented generation. Token budgeting is default; pitch-preserving
  stretch is only applied when requested.
- 2026-05-12: Batch CLI/runtime support dynamic per-row mel-token caps via
  `--dynamic-max-tokens`, `--tokens-per-char`, and `--min-max-tokens` (default
  minimum 320); rows may
  override with `max_tokens`/`max_mel_tokens`.
- 2026-05-12: BigVGAN alias-free padding now uses MLX `mx.pad`; `generate_v2`
  compiles only safe hotpaths (`gpt_layer`, BigVGAN) and leaves CFM eager.
- 2026-05-15: M3 Max 128GB auto profile is enabled through backend-local
  `performance.py`; `memory_limit_gb=None` now means auto-resolve MLX
  memory/cache limits before model load, while explicit `--memory-limit` still
  wins. The verified auto profile is 96GB MLX memory, 32GB MLX cache, and up to
  12 PyTorch preprocessing threads.
